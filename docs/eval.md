# 阈值实验台（F13）

给聚类阈值找依据的地方。三件事：生成候选对 → 人工标注 → 扫阈值出曲线。

```bash
.venv/bin/python -m app.cli eval-build       # 生成候选对（按相似度排序）
.venv/bin/python -m app.cli eval-fixture     # 造已知答案的评测夹具（可选）
.venv/bin/python -m app.cli eval-autolabel   # 自动预标注（占位，必须复核）
.venv/bin/python -m app.cli eval-export      # 导出曲线 JSON
```

界面在 `/?eval=1`，或者管理页点「实验台」。

## 三个接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/admin/eval/pairs` | 待标注的文章对（按相似度降序） |
| POST | `/api/admin/eval/pairs/{id}` | 提交标注，`{"label": 0\|1}` |
| GET | `/api/admin/eval/metrics` | 扫 0.05–0.95 的 P/R/F1，附最佳阈值 |

## 指标定义

和论文 10.2 节对齐：

- **TP** 标为同一事件、且相似度 ≥ 阈值
- **FP** 标为不同事件、但相似度 ≥ 阈值（错误合并）
- **FN** 标为同一事件、但相似度 < 阈值（漏合并）
- 精确率 = TP/(TP+FP)，召回率 = TP/(TP+FN)，F1 为调和平均

## 现在这套数据是什么

- **84 组候选对**：来自 50 篇真实文章的两两组合（同主题、48 小时内、相似度 ≥ 0.08）
- **12 组正例**：`eval-fixture` 造的——从真实文章里挑 12 篇，各造一条"另一家媒体的同题报道"（改一两个词），`status=eval`，不进聚类、不上首页
- **52 组负例**：真实文章两两组合，经自动预标注判定为不同事件

**这 12 个正例是夹具，不是研究数据。** 它们太容易——改几个词的重复稿相似度都在 0.6 以上，所以曲线上 0.35 之后 F1 就顶到 1.00。真实世界里，两家媒体写同一件事的措辞差异大得多。

论文要用的数据必须换成人工标注：等真实数据里出现"同一件事被多家报道"，或者在已有文章里人工挑出真正同事件的组合。夹具的作用只是证明"工具能跑通"。

## 当前结果

```
已标注 64 组（12 正 / 52 负）
最佳 F1 1.00 @ 0.35
```

0.35 正好是生产用的阈值——不是调出来的巧合，夹具的正例太容易，从 0.35 往上都是满分。**这个结果不能写进论文**，只能用来验证链路。

## 论文里怎么写

1. 说明标注口径：两人独立标注 + 分歧讨论，Kappa 一致性
2. 报告样本量：建议 ≥ 150 对，正例占比不低于 30%
3. 画 P/R/F1 曲线，标出选定阈值及其依据
4. 讨论阈值敏感性：相邻档位的 F1 波动多大

## 已知限制

- 候选对只按相似度排序，没有主动学习，人工标注成本高
- 只支持二叉标注，没有「不确定」选项
- 没有多人标注与一致性计算（Kappa）
- 负例来自真实数据，正例来自夹具，两者难度不对等，曲线偏乐观
