# 数据探针报告 · 2026-11-11

**目的**：在写数据模型之前，先验证"源抓不抓得到、正文抽不抽得干净"。对应 PRD 的 F02（定时抓取）、F03（正文抽取）、R01（源失效）、R06（RSS 源失效）。

**方法**：5 个候选源，每源取前 6 条，抓原文页后用 `trafilatura` 抽正文。判据与 F03 一致：正文 ≥ 200 字符记为成功。

**复现**：

```bash
python -m venv .venv
.venv/bin/pip install feedparser trafilatura
.venv/bin/python scripts/probe_feeds.py --per-source 6 --out /tmp/probe.json
```

## 结果

| 源 | 主题 | 语言 | RSS | 抽取成功率 | 正文中位数 | 问题 |
| --- | --- | --- | --- | --- | --- | --- |
| 量子位 | AI | 中文 | ✅ | 5/6 | 4562 字符 | 1 次 SSL 瞬断 |
| InfoQ 中文 | AI | 中文 | ✅ | 6/6 | 1875 字符 | 干净 |
| 爱范儿 | 综合科技 | 中文 | ✅ | 6/6 | 3835 字符 | 干净 |
| Solidot | 综合科技 | 中文 | ✅ | 6/6 | 510 字符 | 每条都带站点头部样板 |
| TechCrunch | AI | 英文 | ✅ | 6/6 | 2582 字符 | 干净 |

**总体抽取成功率 29/30 = 97%**（F03 目标 ≥ 90%，达标）。

## 四个关键发现

### 1. User-Agent 决定生死，不是"建议"

同一批地址，用默认 `curl` UA：

- 量子位 `403`
- InfoQ 中文 `451`
- 机器之心、36氪 返回 SPA 页面

换成浏览器 UA + `Accept-Language: zh-CN` 后全部 `200`。

**结论**：F02 的抓取器必须带完整浏览器请求头，否则首日就有两个源挂掉。

### 2. 97% 的成功率里掺了水

4 个源正文干净，但 Solidot 的每一条正文开头都是：

```
solidot新版网站常见问题，请点击这里查看。 消息 本文已被查看 2295 次 ...
```

这正是 F03 验收标准里写的"无导航栏残留"。按"开头 160 字含导航/样板词"统计，**20%（6/30）的条目有残留，且全部来自 Solidot**。

**结论**：抽取成功率不能只看长度，还要看头部洁净度；Solidot 要么加站点级清洗规则，要么剔除。

### 3. RSS 摘要兜不住

PRD 7.1 写的是"正文抽取失败则用 RSS 摘要截断"。实测摘要长度中位数：

| 源 | RSS 摘要中位数 |
| --- | --- |
| 量子位 | **20 字**（只有标题） |
| 爱范儿 | 67 字 |
| InfoQ 中文 | 134 字 |
| TechCrunch | 151 字 |
| Solidot | 329 字 |

量子位的摘要等于没有，抽失败就是彻底没内容。

**结论**：正文抽取是主路径，不是可选的增强。摘要兜底只对 3 个源勉强成立。

### 4. R01 提前发生了：头部中文科技媒体在关闭 RSS

| 站点 | 尝试 | 结果 |
| --- | --- | --- |
| 机器之心 | `/rss` | 返回 SPA，不是 feed |
| 机器之心 | `/rss/latest` `/api/v4/articles/rss` | SSL 失败 / 404 |
| 36氪 | `/feed` `/feed-newsflash` `/feed-article` | 三个地址返回同一个 25KB SPA 页面 |

**结论**：这两家进不了 MVP 首批源。要覆盖它们只能走 RSSHub 自建实例或站点 API，成本另算。

## 建议的首批源

进 MVP：量子位、InfoQ 中文、爱范儿、Solidot、TechCrunch。

暂缓：机器之心、36氪（等 RSSHub 方案定下来再说）。

未测：Ars Technica、Hacker News（探针时 RSS 正常，留作英文侧补充）。
